## 📖 درباره پروژه

**UNO Tracker** یک پلتفرم کامل و حرفه‌ای برای ثبت، مدیریت و تحلیل بازی‌های کارتی **UNO** است. این پروژه با هدف ارائه یک تجربه‌ی **بلادرنگ**، **گیمیفای شده** و **قابل توسعه** برای علاقه‌مندان به بازی‌های کارتی طراحی و پیاده‌سازی شده است.

### 🧠 فلسفه ساخت

> **"کد نباید قانون‌گذار باشد؛ قانون باید در داده زندگی کند."**

فلسفه‌ی اصلی این پروژه **"Zero Hardcode"** است. به این معنا که:

- **همه‌ی قوانین** بازی (شرایط کسب لقب، نشان‌ها، امتیازات و...) در **دیتابیس** ذخیره می‌شوند.
- **کد PHP فقط یک مجری (Executor)** است که قوانین را از دیتابیس می‌خواند و اجرا می‌کند.
- **مدیر ارشد سیستم** می‌تواند بدون تغییر در کد، قوانین جدید ایجاد کند، القاب جدید تعریف کند، یا نحوه‌ی امتیازدهی را تغییر دهد.

این رویکرد باعث می‌شود:

- **توسعه‌ی سریع‌تر** (بدون نیاز به تغییر کد برای هر قانون جدید)
- **امنیت بالاتر** (مدیریت قوانین توسط ادمین، نه توسعه‌دهنده)
- **انعطاف‌پذیری بی‌نظیر** (قابلیت تغییر قوانین در لحظه)

## 🚀 ویژگی‌های کلیدی

### 🎮 مدیریت بازی

- **ایجاد بازی انفرادی/تیمی** با انتخاب نوع بازی و تعیین هدف برد (Target Wins)
- **چیدمان خودکار تیم** با ۵ الگوریتم مختلف (دستی، تصادفی، بالانس، ضد سینرژی، ضد تکرار)
- **تعیین نوبت اول** با انیمیشن گردونه/سکه
- **ثبت دور** با انتخاب برنده، کارت برنده و نوع برد
- **پایان بازی و تاج‌گذاری** با نمایش انیمیشن و کنفتی

### ⚡ Real-time

- **ارتباط بلادرنگ** با **SSE** (Server-Sent Events) بدون نیاز به WebSocket
- **آپدیت خودکار** تابلو امتیازات و تایم‌لاین دورها
- **نوتیفیکیشن‌های لحظه‌ای** برای رویدادهای مختلف (برد دور، پایان بازی، انتقال لقب و...)
- **پشتیبانی از حالت آفلاین** برای داور (ذخیره در localStorage)

### 🏆 گیمیفیکیشن

- **سیستم XP و سطح‌بندی** (۱۲ سطح با عناوین و رنگ‌های اختصاصی)
- **نشان‌ها (Achievements)** با دسته‌بندی (عمومی، پیروزی، زنجیره، تیمی، ویژه) و کمیابی (معمولی، کمیاب، حماسی، افسانه‌ای)
- **القاب (Titles)** با شرایط خاص و بونوس امتیاز
- **زنجیره‌ی پیروزی (Streak)** با نقاط عطف و اعلان‌های ویژه
- **سیستم شرط‌ساز بصری** برای تعریف قوانین جدید بدون نیاز به کدنویسی

### 👥 تیمی

- **پشتیبانی کامل از بازی‌های تیمی** با امتیازدهی جداگانه برای هر تیم
- **مدیریت اعضای تیم** با قابلیت Drag & Drop
- **نمایش پیشرفت تیم‌ها** با نوارهای پیشرفت رنگی
- **تاریخچه هم‌تیمی‌ها** برای الگوریتم‌های ضد سینرژی

### 🛡️ ضدتقلب

- **سیستم هوشمند تشخیص بازی‌های مشکوک** با سطوح ریسک (کم، متوسط، زیاد، بحرانی)
- **محدودیت‌های ایجاد بازی** (تعداد بازی در ساعت، روز و IP)
- **تشخیص تبانی** با تحلیل الگوی بازی با حریفان محدود
- **مدیریت دسترسی** با کنترل دقیق مجوزهای ساخت بازی و شرکت در بازی

### 📱 PWA

- **قابلیت نصب به‌عنوان اپلیکیشن** روی گوشی موبایل
- **آیکون‌های اختصاصی** برای میانبرهای مختلف (داشبورد، بازی جدید، لیست بازی‌ها، TV، دستاوردها)
- **طراحی واکنش‌گرا** برای تمام دستگاه‌ها

### 📺 TV Mode

- **نمایش اختصاصی بازی‌ها روی تلویزیون** با صفحه‌نمایش بزرگ
- **Wake Lock** برای جلوگیری از خاموش شدن صفحه
- **Auto-Refresh Fallback** در صورت قطع ارتباط SSE
- **دکمه‌های شناور** برای تازه‌سازی، آخرین بازی، لیست بازی‌ها و بازگشت به داشبورد

### 🔐 امنیت

- **احراز هویت با رمز عبور یا کد یکبارمصرف (OTP)**
- **مدیریت کامل دسترسی‌ها** با ماتریس سطوح دسترسی
- **محافظت از Super Admin** در برابر تغییر نقش یا حذف
- **لاگ کامل** از تمام عملیات‌های مدیریتی و اقدامات داوران

### 📊 گزارش‌گیری

- **داشبورد کامل** با نمودارهای پیشرفت، تحلیل عملکرد و مقایسه با رقبا
- **آمار تفصیلی** بر اساس وضعیت بازی، حالت بازی، روزهای هفته و کارت‌های برنده
- **جدول امتیازات** با رتبه‌بندی پویا
- **خروجی CSV** برای کاربران، بازی‌ها، لاگ‌ها و اعلان‌ها

## 🏗️ معماری پروژه

### 📐 لایه‌های معماری (Clean Architecture)

```
┌─────────────────────────────────────────────────────────────────┐
│                    Presentation Layer                           │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────────┐ │
│  │ Controllers │  │ Middleware  │  │ Listeners               │ │
│  │ (HTTP/HTMX) │  │ (Auth/Role) │  │ (Event Handlers)        │ │
│  └─────────────┘  └─────────────┘  └─────────────────────────┘ │
├─────────────────────────────────────────────────────────────────┤
│                    Application Layer                            │
│  ┌─────────────────────────────────────────────────────────────┐│
│  │  Services (Business Logic)                                 ││
│  │  GameService, AuthService, ScoringService, AdminService... ││
│  └─────────────────────────────────────────────────────────────┘│
├─────────────────────────────────────────────────────────────────┤
│                    Domain Layer                                 │
│  ┌─────────────────────────────────────────────────────────────┐│
│  │  Entities & Value Objects                                  ││
│  │  Game, User, Card, Title, Achievement, Team...            ││
│  └─────────────────────────────────────────────────────────────┘│
├─────────────────────────────────────────────────────────────────┤
│                    Infrastructure Layer                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐ │
│  │ Repositories │  │   Database   │  │   SSE (Real-time)    │ │
│  └──────────────┘  └──────────────┘  └──────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 🔄 جریان داده در پروژه

```
[User Request] → [Router] → [Middleware] → [Controller]
                                                   ↓
                                          [Service Layer]
                                                   ↓
                                    [Repository/EventDispatcher]
                                                   ↓
                                    [Database/SSE/View]
                                                   ↓
                                     [Response/Real-time Update]
```

## 🔄 چرخه حیات بازی (Game State Machine)

بازی در هر لحظه فقط می‌تواند در یکی از وضعیت‌های زیر باشد:

| وضعیت                          | توضیح                                                                         |
| ------------------------------ | ----------------------------------------------------------------------------- |
| **`PENDING`** (در انتظار شروع) | داور بازی را ساخته، تیم‌ها را چیده، اما هنوز شروع نکرده است.                  |
| **`ACTIVE`** (در حال اجرا)     | بازی شروع شده، داور در حال ثبت برنده دورهاست.                                 |
| **`PAUSED`** (متوقف)           | داور بازی را موقتاً متوقف کرده است. فقط همان داور می‌تواند Resume کند.        |
| **`FINISHED`** (پایان یافته)   | یک تیم/شخص به `Target Wins` رسیده و داور بازی را بسته است. نتایج قفل می‌شوند. |
| **`CANCELLED`** (لغو شده)      | بازی توسط داور یا مدیر لغو شده و در آمارها محاسبه نمی‌شود.                    |

## 👨‍✈️ فرایند گام‌به‌گام داور (Referee UX Flow)

### گام ۱: ساختار اولیه

- **انتخاب نوع بازی:** ☑️ انفرادی / ☑️ تیمی
- **تعیین هدف برد (Target Wins):** [عدد]
- **انتخاب بازیکنان:** از لیست آنلاین (سیستم به‌صورت خودکار کسانی که در بازی دیگری هستند را غیرفعال/Disable نشان می‌دهد).

### گام ۲: گروه‌بندی (فقط در حالت تیمی)

- **وارد کردن نام تیم‌ها** (مثلاً تیم آبی، تیم قرمز).
- **انتخاب الگوریتم چیدمان:**
  1. **دستی:** Drag & Drop بازیکنان.
  2. **تصادفی:** دکمه 🎲 برای re-roll کردن.
  3. **بالانس (Snake Draft):** چیدن قوی‌ترین با ضعیف‌ترین.
  4. **ضد سینرژی:** جدا کردن کسانی که بیشترین سابقه هم‌تیمی بودن را دارند.
  5. **ضد تکرار:** جلوگیری از تکرار ترکیب ۵ بازی آخر.
- **نکته:** داور همیشه می‌تواند چیدمان پیشنهادی سیستم را قبل از شروع، به صورت دستی اصلاح کند.

### گام ۳: شروع و تعیین نوبت اول

- کلیک روی **«شروع بازی»** (وضعیت به `ACTIVE` تغییر می‌کند).
- نمایش انیمیشن گردونه/سکه برای تعیین کسی که در دنیای واقعی اولین کارت را بازی می‌کند.

### گام ۴: حین بازی (ثبت دور)

داور برای هر دور یک فرم کوچک را پر می‌کند:

1. **برنده:** (انتخاب شخص یا تیم)
2. **کارت برنده:** (انتخاب از گرید بصری کارت‌های فعال)
3. **نوع برد:** (انتخاب از لیست پویا مثل Comeback, Lucky و...)

- **پس از ثبت:** سیستم امتیاز وزنی را محاسبه می‌کند، نوارهای پیشرفت را آپدیت می‌کند، و نوتیفیکیشن‌های SSE را شلیک می‌کند.

### گام ۵: پایان یا توقف

- **اگر برنده به هدف رسید:** دکمه ثبت دور قفل می‌شود. دکمه بزرگ **«پایان بازی و تاج‌گذاری»** ظاهر می‌شود.
- **اگر نیاز به استراحت بود:** داور دکمه **«توقف موقت»** را می‌زند (وضعیت به `PAUSED`).

## 👑 پنل مدیریت (God Mode Dashboard)

پنل مدیریت یک داشبورد تک‌صفحه‌ای (SPA-like با HTMX) است که از سایدبار برای جابه‌جایی بین بخش‌ها استفاده می‌کند.

### 🛡️ ۱. مدیریت کاربران (User Management)

| قابلیت          | توضیح                                                                                 |
| --------------- | ------------------------------------------------------------------------------------- |
| **قابل مشاهده** | لیست کاربران، وضعیت (آنلاین/آفلاین/بن)، تعداد بازی‌ها، امتیاز کل، لقب فعلی، بازی فعال |
| **قابل ویرایش** | تغییر نام مستعار، شعار، بن/آنبن، اخراج اجباری از بازی، ریست آمار                      |
| **نکته امنیتی** | دکمه‌های ویرایش برای **مدیر ارشد** غیرفعال و خاکستری نمایش داده می‌شوند               |

### 🃏 ۲. مدیریت کارت‌ها (Card & Deck Manager)

| قابلیت          | توضیح                                                                                |
| --------------- | ------------------------------------------------------------------------------------ |
| **قابل مشاهده** | گرید تمام کارت‌های تعریف‌شده (فعال و غیرفعال)                                        |
| **قابل ویرایش** | افزودن کارت جدید، ویرایش ضریب (Multiplier)، تغییر کمیابی (Rarity)، فعال/غیرفعال کردن |

### ⚖️ ۳. موتور قوانین و امتیازدهی (Scoring & Rules Engine)

| قابلیت          | توضیح                                                                                                                                           |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **قابل مشاهده** | فرمول‌های فعلی و محدوده‌های سیستم                                                                                                               |
| **قابل ویرایش** | ویرایشگر فرمول امتیاز (مثلاً `{base_score} * {card_multiplier} + {title_bonus}`)، دکمه "تست فرمول"، تعیین محدوده Target Wins، تنظیم سایز تیم‌ها |

### 🏆 ۴. القاب، نشان‌ها و شخصیت‌ها (Titles, Achievements & Playstyles)

| قابلیت          | توضیح                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **قابل مشاهده** | لیست القاب (همراه با دارنده فعلی و رکورد)، نشان‌ها، سبک‌های بازی                                                                                                                                                               |
| **قابل ویرایش** | **سیستم شرط‌ساز بصری (Visual Condition Builder):** به جای JSON، مدیر از UI استفاده می‌کند. مثال: "سلطان کینگ" ← شرط: [نوع کارت] [کینگ] + [تعداد برد متوالی] [≥ ۵] ← سیستم به JSON تبدیل می‌کند. مدیریت پاداش‌ها (Bonus Points) |

### 🔔 ۵. نوتیفیکیشن‌ها و UI (Notifications & UI Customization)

| قابلیت          | توضیح                                                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **قابل مشاهده** | لیست تمام رویدادهای سیستم (`round_won`, `game_finished`, `title_stolen`)                                                          |
| **قابل ویرایش** | ویرایشگر متن با متغیرها (مثلاً `🚨 رکورد شکست! {player} با {streak} برد متوالی لقب {title} را دزدید!`)، آپلود MP3 جدید، پالت رنگی |

### 🎮 ۶. مدیریت بازی‌های فعال (Live Games Control)

| قابلیت                     | توضیح                                                                     |
| -------------------------- | ------------------------------------------------------------------------- |
| **قابل مشاهده**            | لیست بازی‌های در حال اجرا، نام داور، تعداد تماشاگران، وضعیت               |
| **قابل ویرایش (God Mode)** | تغییر داور، ویرایش نتیجه یک دور (با Recalculate خودکار)، پایان/لغو اجباری |

### 🤝 ۷. تنظیمات الگوریتم‌های تیم‌سازی (Team Builder Config)

| قابلیت          | توضیح                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------- |
| **قابل ویرایش** | فعال/غیرفعال کردن هر یک از ۵ الگوریتم، تنظیم وزن الگوریتم بالانس (بر اساس "امتیاز کل" یا "نرخ برد") |

## 🚀 نصب و راه‌اندازی

### 🔧 پیش‌نیازها

- PHP 8.2+
- MySQL 8.0+
- Apache/Nginx
- Composer (اختیاری - برای مدیریت وابستگی‌ها)

### 📦 مراحل نصب

```bash
# ۱. کلون کردن پروژه
git clone https://github.com/persicafzar/uno-tracker.git
cd uno-tracker

# ۲. ایجاد دیتابیس و اجرای اسکریپت SQL
# - یک دیتابیس MySQL ایجاد کنید
# - فایل database/uno_tracker.sql را در آن ایمپورت کنید

# ۳. تنظیم فایل کانفیگ
# - فایل config/database.php را ویرایش کنید
# - نام دیتابیس، username و password را تنظیم کنید

# ۴. تنظیم Document Root
# - Document Root را روی پوشه‌ی public/ تنظیم کنید

# ۵. تنظیم مجوزهای پوشه‌ها
chmod -R 755 storage/
chmod -R 755 public/assets/uploads/

# ۶. کاربر ادمین پیش‌فرض
# - با شماره 09019177577 و رمز admin123 وارد شوید
```

### 🐳 اجرا با Docker (پیشنهادی)

```bash
docker-compose up -d
# سپس به http://localhost:8080 مراجعه کنید
```
