# 📜 سند جامع پروژه (مرحله ۱ از ۳ - نسخه توسعه‌یافته)
## مفاهیم پایه، نقش‌ها، فرایند بازی و معماری

### ۱. استک تکنولوژی و محدودیت‌ها
*   **Backend:** PHP 8.2+ (خالص، کاملاً شی‌گرا، بدون فریم‌ورک).
*   **Database:** MySQL (طراحی نرمال‌سازی شده).
*   **Frontend:** HTML5 + Tailwind CSS (نسخه Standalone CLI برای پروداکشن).
*   **Interactivity:** HTMX (برای ارتباط با سرور و آپدیت تکه‌های HTML) + Alpine.js (برای Stateهای محلی، مودال‌ها، و انیمیشن‌ها).
*   **Real-time:** SSE (Server-Sent Events) در PHP + HTMX SSE Extension.
*   **Charts:** Chart.js یا ApexCharts (از طریق CDN).
*   **قید مطلق:** بدون Node.js، بدون WebSockets، بدون Hardcode کردن قوانین در کد.

### ۲. ماتریس دقیق سطوح دسترسی (Roles & Permissions)

| قابلیت / نقش | مدیر ارشد (Super Admin) | داور (Referee) | بازیکن (Player) | تماشاگر (Spectator) |
| :--- | :---: | :---: | :---: | :---: |
| **دسترسی به پنل God Mode** | ✅ | ❌ | ❌ | ❌ |
| **ایجاد و مدیریت بازی** | ✅ | ✅ (فقط بازی خود) | ❌ | ❌ |
| **ثبت/ویرایش نتیجه دور** | ✅ | ✅ (فقط بازی خود) | ❌ | ❌ |
| **مشاهده پروفایل خود** | ✅ | ✅ | ✅ | ✅ |
| **مشاهده پروفایل دیگران** | ✅ | ✅ | ✅ (فقط خواندنی) | ✅ (فقط خواندنی) |
| **تماشای بازی‌های زنده** | ✅ | ✅ | ✅ (اگر در بازی نیست) | ✅ |
| **شرکت در بازی فیزیکی** | ✅ | ✅ (اختیاری) | ✅ | ❌ |

*   **قانون طلایی:** هر کاربر (به جز مدیر و تماشاگر) **فقط می‌تواند در یک بازی فعال (Active/Paused)** حضور داشته باشد.

### ۳. چرخه حیات بازی (Game State Machine)
بازی در هر لحظه فقط می‌تواند در یکی از وضعیت‌های زیر باشد:
1.  **`PENDING` (در انتظار شروع):** داور بازی را ساخته، تیم‌ها را چیده، اما هنوز دکمه شروع را نزده است.
2.  **`ACTIVE` (در حال اجرا):** بازی شروع شده، داور در حال ثبت برنده دورهاست.
3.  **`PAUSED` (متوقف):** داور بازی را موقتاً متوقف کرده است. فقط همان داور می‌تواند آن را Resume کند.
4.  **`FINISHED` (پایان یافته):** یک تیم/شخص به `Target Wins` رسیده و داور بازی را بسته است. (نتایج قفل می‌شوند).
5.  **`CANCELLED` (لغو شده):** بازی توسط داور یا مدیر لغو شده و در آمارها محاسبه نمی‌شود.

### ۴. فرایند گام‌به‌گام داور (Referee UX Flow)

**گام ۱: ساختار اولیه**
*   انتخاب نوع بازی: ☑️ انفرادی | ☑️ تیمی
*   تعیین هدف برد (Target Wins): [ عدد ]
*   انتخاب بازیکنان از لیست آنلاین (سیستم به صورت خودکار کسانی که در بازی دیگری هستند را غیرفعال/Disable نشان می‌دهد).

**گام ۲: گروه‌بندی (فقط در حالت تیمی)**
*   وارد کردن نام تیم‌ها (مثلاً تیم آبی، تیم قرمز).
*   انتخاب الگوریتم چیدمان:
    1.  *دستی:* Drag & Drop بازیکنان.
    2.  *تصادفی:* دکمه 🎲 برای رeroll کردن.
    3.  *بالانس (Snake Draft):* چیدن قوی‌ترین با ضعیف‌ترین.
    4.  *ضد سینرژی:* جدا کردن کسانی که بیشترین سابقه هم‌تیمی بودن را دارند.
    5.  *ضد تکرار:* جلوگیری از تکرار ترکیب ۵ بازی آخر.
*   **نکته:** داور همیشه می‌تواند چیدمان پیشنهادی سیستم را قبل از شروع، به صورت دستی اصلاح کند.

**گام ۳: شروع و تعیین نوبت اول**
*   کلیک روی «شروع بازی» (وضعیت به `ACTIVE` تغییر می‌کند).
*   نمایش انیمیشن گردونه/سکه برای تعیین کسی که در دنیای واقعی اولین کارت را بازی می‌کند.

**گام ۴: حین بازی (ثبت دور)**
*   داور برای هر دور یک فرم کوچک را پر می‌کند:
    1.  **برنده:** (انتخاب شخص یا تیم)
    2.  **کارت برنده:** (انتخاب از گرید بصری کارت‌های فعال)
    3.  **نوع برد:** (انتخاب از لیست پویا مثل Comeback, Lucky و...)
*   *پس از ثبت:* سیستم امتیاز وزنی را محاسبه می‌کند، نوارهای پیشرفت را آپدیت می‌کند، و نوتیفیکیشن‌های SSE را شلیک می‌کند.

**گام ۵: پایان یا توقف**
*   اگر برنده به هدف رسید: دکمه ثبت دور قفل می‌شود. دکمه بزرگ «پایان بازی و تاج‌گذاری» ظاهر می‌شود.
*   اگر نیاز به استراحت بود: داور دکمه «توقف موقت» را می‌زند (وضعیت به `PAUSED`).

# 📜 سند جامع پروژه (مرحله ۲ از ۳)
## کالبدشکافی پنل مدیریت (God Mode) و معماری دیتابیس

---

### بخش اول: معماری دیتابیس (MySQL) با رویکرد "Zero Hardcode"

برای اینکه پنل مدیریت بتواند همه چیز را کنترل کند، دیتابیس ما نباید فقط "داده" ذخیره کند، بلکه باید "قوانین و متادیتا" را نیز در خود جای دهد. ما از جداول رابطه‌ای استاندارد در ترکیب با فیلدهای `JSON` برای شرایط پیچیده استفاده می‌کنیم.

#### ۱. جداول هسته بازی (Core Game Tables)
*   **`users`**: اطلاعات کاربران (شامل `role`, `status`, `playstyle_id`, `current_title_id`).
*   **`games`**: اطلاعات بازی (شامل `referee_id`, `mode`, `target_wins`, `status`, `team_builder_algorithm`).
*   **`game_participants`**: ارتباط بازیکنان/تیم‌ها با بازی (شامل `team_id`, `user_id`, `guest_name`, `wins_count`).
*   **`game_rounds`**: ثبت هر دور (شامل `winner_id`, `winning_card_id`, `win_type_id`).

#### ۲. جداول داینامیک و قوانین (Dynamic Rules Tables) - *بخش حیاتی*
این جداول توسط مدیر ارشد پر و خالی می‌شوند و کد PHP فقط آن‌ها را می‌خواند:

*   **`cards` (مدیریت کارت‌ها):**
    *   `id`, `name`, `icon_path`, `description`, `rarity` (enum: common, rare, legendary), `score_multiplier` (DECIMAL), `is_active` (BOOLEAN).
*   **`win_types` (انواع برد):**
    *   `id`, `name`, `icon`, `score_multiplier`, `is_active`.
*   **`playstyles` (شخصیت‌ها و سبک‌های بازی):**
    *   `id`, `name`, `icon`, `color_hex`, `condition_json` (JSON).
    *   *مثال JSON:* `{"rule": "win_percentage_by_rarity", "rarity": "legendary", "min_percent": 40}`
*   **`titles` (القاب انتقالی و رکوردداران):**
    *   `id`, `name`, `icon`, `color_hex`, `condition_json`, `bonus_points`, `current_holder_id`, `record_value`, `is_active`.
*   **`achievements` (نشان‌های دائمی):**
    *   `id`, `name`, `icon`, `condition_json`, `is_active`.
*   **`notification_templates` (قالب‌های اعلان):**
    *   `id`, `event_name` (مثل `round_won`), `text_template` (مثل `تبریک {player} با {card} بردی!`), `color_hex`, `sound_file`, `is_active`.
*   **`settings` (تنظیمات عمومی و فرمول‌ها):**
    *   `key` (PK), `value`, `type` (string, int, json).
    *   *مثال:* کلید `formula_final_score` با مقدار `"{base} * {card_mult} + {win_type_mult}"`.

#### ۳. جداول آماری و کش (Analytics & Cache)
*   **`leaderboard_cache`**: برای لود شدن داشبورد در زیر ۱۰۰ میلی‌ثانیه. شامل `user_id`, `total_points`, `win_rate`, `matches_played`. (با هر پایان بازی، فقط ردیف‌های مربوطه آپدیت می‌شوند).
*   **`card_mastery`**: رکورد هر کاربر در هر کارت. `user_id`, `card_id`, `max_streak`, `total_wins`.
*   **`admin_audit_log`**: ثبت تمام تغییرات مدیر (چه کسی، چه چیزی را، کی تغییر داد).

### بخش دوم: کالبدشکافی پنل مدیریت (God Mode Dashboard)

پنل مدیریت یک داشبورد تک‌صفحه‌ای (SPA-like با HTMX) است که از سایدبار برای جابه‌جایی بین بخش‌ها استفاده می‌کند. در ادامه، دقیقاً مشخص می‌کنیم در هر بخش چه چیزی **قابل مشاهده** و چه چیزی **قابل ویرایش** است.

#### 🛡️ ۱. بخش مدیریت کاربران (User Management)
*   **قابل مشاهده:** لیست تمام کاربران، وضعیت (آنلاین/آفلاین/بن)، تعداد بازی‌ها، امتیاز کل، لقب فعلی، و بازی فعالی که در آن هستند.
*   **قابل ویرایش/اقدام:**
    *   تغییر نام مستعار، شعار، یا ریست کردن عکس پروفایل.
    *   بن/آنبن کردن کاربر (تغییر `status`).
    *   **اخراج اجباری از بازی:** اگر کاربری در یک بازی گیر کرده و داور در دسترس نیست، مدیر می‌تواند او را از بازی خارج کند.
    *   **ریست کردن آمار:** صفر کردن کامل امتیازات و نشان‌های یک کاربر (با ثبت لاگ).
    *   *نکته امنیتی:* دکمه‌های ویرایش و حذف برای ردیفِ مربوط به **مدیر ارشد (Super Admin)** غیرفعال (Disable) و خاکستری نمایش داده می‌شوند.

#### 🃏 ۲. بخش مدیریت کارت‌ها (Card & Deck Manager)
*   **قابل مشاهده:** گرید تمام کارت‌های تعریف شده (فعال و غیرفعال).
*   **قابل ویرایش:**
    *   **افزودن کارت جدید:** نام، آپلود آیکون (یا انتخاب از ایموجی‌ها)، توضیحات.
    *   **ویرایش ضریب (Multiplier):** تغییر ضریب امتیاز (مثلاً تغییر ضریب کارت کینگ از ۲.۰ به ۳.۰).
    *   **تغییر کمیابی (Rarity):** جابه‌جایی کارت بین معمولی، نادر و افسانه‌ای.
    *   **فعال/غیرفعال کردن (Toggle):** اگر کارتی در بازی فیزیکی گم شده یا بالانس بازی را به هم زده، مدیر آن را غیرفعال می‌کند تا در دراپ‌داون داوران نمایش داده نشود.

#### ⚖️ ۳. بخش موتور قوانین و امتیازدهی (Scoring & Rules Engine)
*   **قابل مشاهده:** فرمول‌های فعلی و محدوده‌های سیستم.
*   **قابل ویرایش:**
    *   **ویرایشگر فرمول امتیاز:** یک فیلد متنی که فرمول را می‌گیرد. مثلاً: `{base_score} * {card_multiplier} + {title_bonus}`. سیستم یک دکمه "تست فرمول" دارد که با اعداد فرضی آن را محاسبه و پیش‌نمایش می‌کند.
    *   **محدوده‌های سیستم:** تعیین حداقل و حداکثر `Target Wins` (مثلاً حداقل ۳، حداکثر ۵۰).
    *   **تنظیمات تیم‌ها:** تعیین سایز مجاز تیم‌ها (مثلاً فقط ۲ یا ۳ نفره).

#### 🏆 ۴. بخش القاب، نشان‌ها و شخصیت‌ها (Titles, Achievements & Playstyles)
این بخش پیچیده‌ترین و جذاب‌ترین قسمت پنل است.
*   **قابل مشاهده:** لیست القاب (همراه با دارنده فعلی و رکورد)، نشان‌ها، و سبک‌های بازی.
*   **قابل ویرایش (سیستم شرط‌ساز بصری - Visual Condition Builder):**
    *   به جای نوشتن JSON، مدیر از یک UI استفاده می‌کند.
    *   *مثال ساخت لقب "سلطان کینگ":*
        1. نام: سلطان کینگ | آیکون: 👑
        2. شرط: [نوع کارت] [برابر است با] [کینگ] + [تعداد برد متوالی] [بیشتر یا مساوی] [۵]
        3. سیستم این را به JSON تبدیل کرده و در دیتابیس ذخیره می‌کند.
    *   *مثال ساخت سبک "دیکتاتور":*
        1. نام: دیکتاتور | رنگ: قرمز
        2. شرط: [درصد بردها با کارت‌های] [کمیابی: افسانه‌ای] [بیشتر از] [۴۰٪]
    *   **مدیریت پاداش‌ها:** تعیین اینکه هر لقب یا نشان چند امتیاز جایزه (Bonus Points) به کاربر می‌دهد.

#### 🔔 ۵. بخش نوتیفیکیشن‌ها و UI (Notifications & UI Customization)
*   **قابل مشاهده:** لیست تمام رویدادهای سیستم (مثل `round_won`, `game_finished`, `title_stolen`).
*   **قابل ویرایش:**
    *   **ویرایشگر متن:** تغییر متن اعلان‌ها با استفاده از متغیرها. مثلاً: `🚨 رکورد شکست! {player} با {streak} برد متوالی لقب {title} را دزدید!`
    *   **مدیریت صداها:** آپلود فایل MP3 جدید یا انتخاب از کتابخانه صداهای موجود برای هر رویداد.
    *   **پالت رنگی:** تغییر کد HEX رنگ نوتیفیکیشن‌ها (مثلاً تغییر رنگ برد از سبز به طلایی).

#### 🎮 ۶. بخش مدیریت بازی‌های فعال (Live Games Control)
*   **قابل مشاهده:** لیست تمام بازی‌های در حال اجرا (Active/Paused)، نام داور، تعداد تماشاگران، و وضعیت فعلی.
*   **قابل ویرایش/اقدام (دسترسی God Mode):**
    *   **تغییر داور:** اگر داور بازی را رها کرد، مدیر می‌تواند داور را به شخص دیگری تغییر دهد.
    *   **ویرایش نتیجه یک دور:** اگر داور اشتباه ثبت کرد، مدیر می‌تواند وارد تایم‌لاین بازی شده و برنده/کارت دور خاصی را تغییر دهد (سیستم به صورت خودکار امتیازات و القاب را Recalculate می‌کند).
    *   **پایان/لغو اجباری:** پایان دادن دستی به بازی یا لغو کامل آن (Cancel).

#### 🤝 ۷. بخش تنظیمات الگوریتم‌های تیم‌سازی (Team Builder Config)
*   **قابل ویرایش:**
    *   فعال/غیرفعال کردن هر یک از ۵ الگوریتم (دستی، تصادفی، بالانس، ضدسینرژی، ضدتکرار).
    *   **تنظیم وزن الگوریتم بالانس:** مدیر می‌تواند تعیین کند که در الگوریتم "ضعیف با قوی"، سیستم بر اساس "امتیاز کل" بازیکنان را بچیند یا "نرخ برد (Win Rate)".

### بخش سوم: موتور ارزیابی قوانین (Rule Engine) - جادوی پشت صحنه

چگونه این تنظیمات پنل مدیریت در حین بازی اعمال می‌شوند بدون اینکه کد PHP تغییر کند؟

ما یک کلاس به نام `RuleEvaluator` داریم. وقتی رویدادی مثل `RoundEnded` رخ می‌دهد، این کلاس فراخوانی می‌شود:

1.  **دریافت Context:** کلاس وضعیت فعلی را می‌گیرد (مثلاً: کاربر X با کارت Y برنده شد، این سومین برد متوالی اوست).
2.  **خواندن از دیتابیس:** تمام `condition_json` های فعال را از جداول `titles`, `achievements`, `playstyles` می‌خواند.
3.  **ارزیابی پویا (Dynamic Parsing):** کلاس JSON را پارس می‌کند. 
    *   *مثال:* اگر JSON بگوید `{"rule": "streak", "card_id": 5, "min": 3}`، کلاس چک می‌کند آیا کاربر ۳ بار متوالی با کارت ۵ برده است؟
4.  **اقدام (Action):** اگر شرط برقرار بود، کلاس به صورت خودکار:
    *   لقب را در جدول `titles` آپدیت می‌کند.
    *   نشان را در جدول `user_achievements` insert می‌کند.
    *   نوتیفیکیشن مربوطه را از `notification_templates` خوانده و متغیرها را جایگزین می‌کند.

**نتیجه:** کد PHP ما فقط یک "مجری" (Executor) است. "قانون‌گذار" واقعی، مدیر ارشد از طریق پنل مدیریت و دیتابیس است.

### بخش دوم: کامپوننت‌های تعاملی و تجربه کاربری (UX)

در این بخش، نحوه پیاده‌سازی ویژگی‌های پیچیده UX را با استفاده از **HTMX** و **Alpine.js** (بدون Node.js) تشریح می‌کنیم.

#### ۱. حالت آفلاین داور (Offline-First Referee Mode)
از آنجا که اینترنت در محیط‌های بازی فیزیکی ممکن است قطع شود، داور نباید نتیجه‌ای را از دست بدهد.
*   **پیاده‌سازی با Alpine.js:**
    *   یک کامپوننت Alpine روی فرم ثبت دور داور قرار می‌گیرد.
    *   وقتی داور دکمه "ثبت" را می‌زند، Alpine ابتدا `navigator.onLine` را چک می‌کند.
    *   **اگر آنلاین بود:** درخواست HTMX به سرور ارسال می‌شود.
    *   **اگر آفلاین بود:** داده در `localStorage` (در یک آرایه به نام `offlineQueue`) ذخیره می‌شود. یک نشانگر زرد رنگ "⏳ در صف انتظار" روی صفحه ظاهر می‌شود.
    *   **بازگشت اینترنت:** Alpine به رویداد `window.addEventListener('online', ...)` گوش می‌دهد. به محض اتصال، صف را خوانده و درخواست‌ها را یکی‌یکی به سرور می‌فرستد و نشانگر را به "✅ همگام‌سازی شد" تغییر می‌دهد.

#### ۲. مشاهده پروفایل دیگران (Read-Only Profile Drawer)
برای جلوگیری از رفرش شدن صفحه و از دست رفتن Context (مثلاً وقتی در حال تماشای بازی زنده هستید):
*   **پیاده‌سازی:**
    *   روی نام هر کاربر در سراسر برنامه، یک ویژگی HTMX به نام `hx-get="/users/{id}/profile-partial"` و `hx-target="#profile-drawer"` قرار می‌دهیم.
    *   سرور به جای یک صفحه کامل، فقط **HTML Fragment** (تکه‌های HTML پروفایل) را برمی‌گرداند.
    *   یک کامپوننت Alpine یک **Drawer (پنل کشویی از سمت راست)** را مدیریت می‌کند. با دریافت HTML، Drawer با انیمیشن `transform translate-x` باز می‌شود.
    *   پس‌زمینه صفحه تار (Backdrop Blur) می‌شود تا تمرکز روی پروفایل باشد.

#### ۳. انیمیشن‌های انتقال لقب و تاج‌گذاری (Epic Moments)
وقتی سیستم رویداد (Event System) تشخیص می‌دهد که لقبی دزدیده شده یا بازی به پایان رسیده:
*   **پیاده‌سازی:**
    *   سرور یک نوتیفیکیشن SSE با تایپ `title_stolen` یا `game_finished` ارسال می‌کند.
    *   در فرانت‌اند، یک Listener در Alpine.js این رویداد را می‌شنود.
    *   یک **مودال تمام‌صفحه (Overlay)** با افکت شیشه‌ای (Glassmorphism) باز می‌شود.
    *   **انیمیشن‌ها:** آیکون لقب با افکت `scale` و `rotate` وارد می‌شود. از کتابخانه سبک **canvas-confetti** (از CDN) برای بارش کانفتی استفاده می‌شود.
    *   **صدا:** فایل صوتی مربوطه (که مدیر از پنل تنظیم کرده) با استفاده از `new Audio()` در جاوااسکریپت پخش می‌شود.

### بخش سوم: پیاده‌سازی Real-time با SSE در PHP خالص

ما به جای WebSockets، از **Server-Sent Events (SSE)** استفاده می‌کنیم که کاملاً با PHP خالص و هاست‌های اشتراکی سازگار است.

**نحوه کار `SseController.php`:**
1.  **تنظیم هدرها:**
    ```php
    header('Content-Type: text/event-stream');
    header('Cache-Control: no-cache');
    header('Connection: keep-alive');
    ```
2.  **حلقه بی‌نهایت (Long Polling داخل SSE):**
    ```php
    while (connection_aborted() === 0) {
        // ۱. چک کردن دیتابیس یا فایل کش برای رویدادهای جدید از زمان آخرین ارسال
        $events = $sseRepository->getNewEvents($lastEventId);
        
        // ۲. اگر رویدادی بود، ارسال به کلاینت
        if (!empty($events)) {
            foreach ($events as $event) {
                echo "id: " . $event['id'] . "\n";
                echo "event: " . $event['type'] . "\n"; // مثلاً round_won
                echo "data: " . json_encode($event['payload']) . "\n\n";
            }
            flush();
            ob_flush();
        }
        
        // ۳. استراحت کوتاه برای جلوگیری از اشغال ۱۰۰٪ CPU سرور
        usleep(500000); // ۰.۵ ثانیه
    }
    ```
3.  **در فرانت‌اند (HTMX SSE Extension):**
    ```html
    <div hx-ext="sse" sse-connect="/sse/game-updates/123" sse-swap="round_won,game_finished">
        <!-- محتوای اینجا با هر رویداد از سرور آپدیت می‌شود -->
    </div>
    ```
